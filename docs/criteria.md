# 收录标准

这份文档存在的唯一目的：**让「这个能不能收」有一个不依赖维护者心情的答案。**

有争议时先看这里；这里没写的，按 [GOVERNANCE.md](../GOVERNANCE.md) 处理，并把结论补进来。

---

## 一句话原则

**收「能帮人把招投标或工程建设里的某个环节做得更快、更准、更省」的东西，并且读者点进去能自己判断它适不适合。**

---

## 收什么

同时满足这五条才收：

| 条件 | 具体要求 |
| --- | --- |
| **真实存在** | 链接可访问，不是占位页、预售页、已下线项目 |
| **可获取** | 开源，或者有免费可用的版本/额度。纯付费墙后的产品不收 |
| **业务相关** | 见下面「关联度怎么判断」 |
| **能用** | 有文档、有示例，或者至少能装起来跑；不是只有一个 README 的空仓库 |
| **有人在维护** | 近 24 个月有提交或发布。停止维护但有参考价值的可标 `archived: true` 保留 |

### 关联度怎么判断

分三档，只有前两档收：

**A. 业务专用** —— 就是干这行的。招标公告采集器、标书排版工具、清单计价软件、围串标分析。直接收。

**B. 通用但在这行高频** —— 本身是通用工具，但在招投标/工程流程里几乎绕不开：PDF 解析、OCR、Word/Excel 自动化、国密算法、BIM/CAD、甘特图、GIS。**收，但描述里必须写清具体环节**，否则它就只是一条普通工具，读者不知道为什么要在这里看它。

判断 B 档的土办法：如果去掉招投标场景，这个项目在列表里还站得住吗？站不住 = 描述没写好；站得住但跟本行业毫无关系 = 不收（比如「宇宙最强的 Rust Web 框架」）。

**C. 无关** —— 不收。除非它解决的是本行业公认的痛点（比如中文分词），并且描述能把这个痛点说清楚。

## 明确不收

### 合规红线（硬性，无例外）

招投标是强监管领域，以下一律不收，也不接受「只是技术工具」的辩解：

- **破解 / 绕过类**：破解标书查重、破解计价软件加密锁、绕过实名认证、伪造 CA 证书、伪造电子签章
- **围标串标辅助**：批量代做多家投标文件、操控报价分布的「陪标生成器」
- **数据窃取**：抓取需登录的投标人信息、爬取他人标书、撞库或账号池
- **规避监管**：承诺「不触发雷同检测」的改写工具、伪造业绩或资质的模板生成器

判断标准很简单：**这东西的主要用途，是不是让某个人在监管面前看起来不是他本来的样子？** 是，就不收。

### 其他不收

- 纯营销落地页、SEO 农场、聚合下载站、网盘链接
- 无免费层的商业 SaaS（可以在 Discussions 里推荐，但不进列表）
- 已下线 / 域名过期 / 仓库 404
- 只有一个 README 的空壳项目、明显的作业/练习仓库
- 与行业无关的通用项目（「又一个前端框架」）
- 侵权内容（盗版教程、破解版安装包、未授权转载的付费文档）

## 灰区怎么判

这些情况经常被问，先给结论：

| 情况 | 结论 | 理由 |
| --- | --- | --- |
| 商业软件但有免费社区版 | **收**，`license: proprietary`，`notes` 写清免费边界 | 读者需要知道有这条路，但要能自己判断成本 |
| 已归档 3 年，但仍是事实标准 | **收**，`archived: true` | 不能用≠没价值，标注比删掉有用 |
| 作者是个人，仓库只有 20 star | **收** | 有用就行，star 不是门槛。但要求有文档 |
| AI 代写标书工具（开源） | **收**，`notes` 提示合规 | 写标书本身合法，违规的是围标。别把工具和用法混为一谈 |
| 通用大模型框架（LangChain 等） | **收**，但必须写清在标书/法规场景的具体用法 | 属于 B 档，描述不绑定场景就退 |
| 微信公众号文章 / 知乎专栏 | **不收** | 不是「可用的东西」，是内容。除非是做成了持续维护的站点/工具 |
| 自己写的模板库（Word 标书模板） | **收**（`kind: dataset`），前提是有版本管理、能持续更新 | 这类东西的坑最多，作者得愿意维护 |
| 付费课程的免费试看 | **不收** | 商业内容导流 |
| 公司内部系统开源出来 | **收** | 有源码就能用，跟作者是谁无关 |
| 项目已改名/迁移 | **收新地址**，旧条目更新 URL；彻底没了就标 archived | 不要因为搬家就删条目 |

## 维护状态怎么算

| 状态 | 判据 | 处理 |
| --- | --- | --- |
| 活跃 | 近 6 个月有提交 | 正常 |
| 缓慢 | 6~24 个月有提交 | 正常，`notes` 可注明 |
| 停滞 | 超过 24 个月无提交，但仍能安装使用 | 收，`archived: true` |
| 死亡 | 无法安装、依赖全部失效、文档站下线 | 删除条目 |

`npm run enrich` 会抓 `pushedAt` 与 `archived`，`npm run link-check` 会抓链接状态，两者一起看就能判断。

## 下架规则

条目被收录后不会因为「维护者不喜欢」而下架。只有这几种情况会移出列表：

1. 上游已彻底不可用（安装不了、所有下载源失效）
2. 被发现含恶意代码或后门
3. 许可变更导致「免费可用」不再成立
4. 项目方明确要求移除（会尊重，但会在 issue 里留记录）

下架不是删除历史：改动会留在 git 里，issue 里写明原因。
